# 更新日志

## v1.4.1 (2026-10-05)

群相册上传链路提速，参数与收尾修复对齐 astrbot_plugin_weibo_album v1.9.x 的实测结论。相册里的产物不变（仍是 `/large/` 原图）。

### 改进

- **推送消息带图改用 `mw2000` 轻量档**：消息里的图片由协议端（NapCat）自己去 sina CDN 远程抓取，此前塞的是 `/large/` 原图直链——单张 5~30MB、九张串在一条消息里很容易顶穿 `message_send_timeout`（默认 60 秒），超时按发送失败进重试还会让同一条微博在群里重复出现。`mw2000`（长边 2000px）是微博 CDN 原生尺寸，改一个路径段就有，不需要本地下载与压缩；群相册那条路仍传原图。
- **默认载荷下不再回读相册媒体列表**：base64 载荷会被 NapCat 改名成 randomUUID，相册文件名里不含微博 pid，"文件名比对去重"必然不命中，却要为每批图串行翻最多 8 页媒体列表（一页一次协议端往返）。现只在 `album_same_host`（本地路径传图、相册保留图片名）时回读；台账去重不受影响。
- **并发/间隔默认值对齐上游实测**：上传并发 `2 → 3`、张间隔 `1.0 → 0.5` 秒、下载并发 `3 → 5`。协议端传相册是每张内部串行发 16KB 分片，单张本身就慢，同时在传的张数基本等于吞吐；间隔只用来错开起点防撞频控。撞频控时先调大间隔、其次调低并发。
- **分阶段耗时日志**：每批图片在两个重负载动作之前各记一行，收场汇总"成功张数 / 上传耗时 / 体积 / 下载耗时"，慢在下载还是上传、当时在传多大一批，日志一眼可见。

### 修复

- **风控 HTML 页不再被当成图片**：下载拒 `Content-Type: text/html` 的 200 响应。此前只按体积（>1KB）判成功，被风控拦下时返回的错误页会存成 `.jpg` 一路传进群相册，报错推迟到 ffmpeg 转码或上传时才爆。
- **批次目录清理移出事件循环**：整批几十到几百 MB 的 `rmtree` 是阻塞调用，原先直接在事件循环里跑，能把整个 AstrBot 钉住数秒，同批其他群的推送与轮询跟着一起卡。
- **同机模式首张探路**：`album_same_host` 开启且尚未学到可用载荷方式时，第一张图先单独上传，学到可用方式后再放开并发。此前整批一起拿本地路径去撞协议端，两边不同机时每张一条 ENOENT、每张多跑一趟载荷降级。

### 安全

- **代理地址不再泄露凭据**：`proxy` 若填成 `http://user:pass@host:port`，此前会原样出现在启动日志里，并被 `微博状态`（不限权限，群成员都可触发）整条回显。现统一打码为 `http://***@host:port` 再输出，实际请求仍用完整地址。
- **文档示例 uid 改为占位**：README 与指令用法里的示例 uid 换成 `1234567890`，不再指向某个真实博主主页。

### 兼容性

- 无破坏性变更：图片尺寸档、相册规则格式、台账键位都没动；三项并发/间隔配置若在 WebUI 手工填过值，仍沿用你填的，本次只改默认值。
- 默认部署（`album_same_host=false`）下不再做相册文件名回读：若同一批图曾被其他相册插件以本地路径方式传过（相册里保留着微博文件名），本插件不再据此跳过——两边的台账本就互相独立，手动补传时留意相册里多出重复。

## v1.4.0 (2026-10-04)

整合群相册上传能力（参考 astrbot_plugin_weibo_album 的实践方案内嵌实现）：微博转发到Q群后，自动把微博内的图片上传到指定群相册，不同博主可绑定不同相册。

### 新增

- **图片自动进群相册**：`微博相册绑定 <uid> <相册名或ID>`（群内使用）把博主的微博图片绑定到本群相册；推送成功后自动提取微博图片（含转发原微博的图）→ 下载 `/large/` 原图 → 经 NapCat 的 OneBot 扩展接口 `upload_image_to_qun_album` 传进相册。配套指令：`微博相册移除` / `微博相册列表` / `微博列相册`
- **实况图转 GIF**：livephoto 优先用 ffmpeg 转 GIF 上传（限帧率压体积、CPU 并发闸、60 秒超时），未装 ffmpeg 或转换失败时自动回落封面静图；纯视频条目跳过（群相册接口仅支持图片）
- **推送消息附带图片**：`message_with_images`（默认开）开启后推送消息在文本后附带微博原图，图片数受 `album_max_images`（默认 9）上限约束
- **多级防重复上传**：按图片 pid 记录 KV 上传台账（保留 30 天、每相册 2000 条）+ 相册已有文件名比对，重启/重发不重传；(群, 相册) 解析结果内存缓存 1 小时，减少翻列表请求
- **上传频控三层闸**：并发数（默认 2）+ 张间隔（默认 1 秒）+ 在途 base64 载荷字节预算（默认 32MB，按 1.5 倍原图体积计）；同一群的批次串行化，上传任务异步执行不阻塞轮询
- **安全边界**：图片/视频段下载域名白名单（sinaimg/weibocdn 系）+ DNS 解析拒绝内网与保留地址 + 单张 30MB 上限 + 磁盘余量 ≥1GB 保护；下载流式落盘、`.part` 原子改名、传完即删、启动清理残留
- **bot 连接获取**：轮询型插件无消息事件，改从 `platform_manager.get_insts()` 按 platform_id 匹配 aiocqhttp 适配器实例的 CQHttp 客户端；`self_id` 通过 `get_login_info` 懒加载缓存
- 相关配置项：`album_enabled` / `album_rules` / `album_max_images` / `album_download_concurrency` / `album_upload_concurrency` / `album_upload_interval` / `album_upload_payload_mb` / `album_same_host` / `album_live_gif` / `album_notify` / `message_with_images`

### 兼容性说明

- 群相册上传要求 NapCat ≥ v4.8.101（旧版协议端无群相册接口，上传时会明确报错）；Lagrange 等其他协议端暂不支持
- 实况图转 GIF 需要服务器安装 ffmpeg；未安装时功能自动降级（传封面静图），不影响其余功能
- 旧版本 `state.json` 无需迁移：待推送条目的图片字段按缺省处理，自动兼容
- 现要求 AstrBot ≥ v4.9.2（上传台账使用 KV 存储；已通过 metadata 的 `astrbot_version` 声明，旧版本将明确提示不兼容而非静默降级）
- 补齐 metadata 的 `author` / `repo` 信息（此前为模板占位符）

## v1.3.0 (2026-10-03)

代码审计修复与逻辑优化，行为兼容 v1.2.0：

### 修复

- **多群推送短路 bug**：`_flush_pending` 中 `sent = sent or await ...` 短路求值，导致绑定多个群时只有第一个群实际收到推送（后续群被跳过）；现逐群发送，任一群成功即视为该条完成
- **超长微博全文被截断**：`show_full_weibo_text` 拉回的全文被 `text_max_length`（默认 100 字）二次截断，功能形同虚设；现全文使用独立安全上限（2000 字符），不再受摘要长度影响
- **转发原微博长文**：开启全文模式后，转发的原微博超长时同样通过 `/statuses/extend` 拉取全文
- **风控梯度永不重置**：`_risk_level` 只升不降，历史上偶发 3 次 432 后冷却永久固定 60 分钟；现距上次触发超过 2 小时自动重置梯度
- **冷却期内叠加升级**：同一轮请求中多次 432（主请求 + 换身份重试）会连续推高冷却梯度；现冷却期内重复触发不再叠加升级

### 改进

- **`custom_cookie` 真正生效**：此前该配置项仅有面板定义、代码从未使用；现填写后插件跳过游客身份流程（预热/续期/换新），直接用自定义 Cookie 请求接口，失效时明确报错
- **冷却期出网拦截**：风控冷却期间 `_api_get` 直接快速失败，`微博添加` 等指令触发的请求不再穿透冷却继续打到微博
- **并发加固**：请求间隔（`_pace`）与游客续期（`_renew_visitor`）加锁串行，指令处理与轮询任务并发时不再出现间隔失效、双重换新
- **待推送队列健壮性**：`state.json` 载入时校验条目结构并补默认值，超限截断；重试计数改用防御性读取
- **细节**：`_get_text` 最后一次重试后不再多余等待；账号重试判断改用实时时间（修复长轮询中过期 `now` 导致的误跳过）；`微博检测` 在已有检查进行中时明确提示；日志措辞「推送」修正为「检测到」（检测数含被过滤微博）

## v1.2.0 (2026-10-03)

参考同类优秀项目（jiantoucn/astrbot_plugin_weibo_monitor）做的功能增强，保持免 Cookie 架构不变：

- 新增 **自定义消息模板** `message_format`：支持 `{name}`/`{time}`/`{weibo}`/`{link}` 占位符与 `\n` 换行
- 新增 **屏蔽词 / 白名单关键词过滤**：正文命中屏蔽词不推送；配置白名单后仅推送命中关键词的微博
- 新增 **时效过滤** `max_post_age_minutes`：不推送过旧微博，失败重试的过期待办自动清除，保持"实时转发"语义
- 新增 **超长微博全文** `show_full_weibo_text`：通过 `/statuses/extend` 获取全文（游客身份实测可用），失败自动回退摘要
- 新增 **消息发送超时** `message_send_timeout`：防止单个平台适配器无响应卡住轮询任务；发送返回 False 视为失败并进入重试
- 拉取全文的额外请求同样纳入全局请求间隔与风控冷却体系

## v1.1.0 (2026-10-03)

基于微博对游客访问的反爬/限流调研（432 自定义风控码：游客身份过期、频率/累计量、IP 信誉三类因素叠加）做稳定性加固：

- 432/418 **全局冷却**：IP 级风控不再按账号重试，10→30→60 分钟梯度升级，成功一次即解除
- **游客身份续期节制**：复用 3 天、换新间隔 ≥10 分钟、每小时最多 3 次、失败指数退避
- **全局请求间隔闸**：任意两次微博请求强制 2~5 秒随机间隔
- **UA 与游客身份绑定**：UA 池随机选取并随身份持久化，保持指纹一致性
- **启动预热**：重启后先访问主页刷新 `_T_WM`/XSRF 指纹
- 新增可选 **proxy 配置**：海外/VPS 部署可走国内出口代理

- 基线机制防历史微博刷屏、推送失败重试、账号级指数退避、状态持久化
